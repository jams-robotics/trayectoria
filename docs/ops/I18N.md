# Internacionalización (i18n)

Cómo se manejan los textos de interfaz de Trayectoria (F0-06). Toda cadena visible de la interfaz vive en un archivo de locale y se consume por clave; el idioma por defecto es `es`. El contenido de los temas (MDX) **no** pasa por aquí: va por carpeta de idioma (`content/es/`, `content/en/` en el futuro; `ARCHITECTURE.md` §3.3).

## 1. Qué hay en `packages/i18n`

| Archivo | Qué es |
|---|---|
| `locales/es/common.json` | Todas las claves con sus valores en español. Único namespace (`common`). |
| `src/t.ts` | Instancia propia de i18next (`createInstance()`) inicializada de forma **sincrónica** con los recursos incrustados (`initAsync: false`) y el helper `t(key, params?)`. |
| `src/useT.ts` | Hook `useT()` para islas React: devuelve `t` y re-renderiza el componente al cambiar el idioma (`useSyncExternalStore` suscrito al evento `languageChanged`). |
| `src/index.ts` | API pública: `t`, `useT`, `DEFAULT_LANGUAGE` y los tipos `TParams`, `Translate`. |
| `src/keys.test.ts` | Test estático: falla si el código usa una clave que no existe en `common.json`. |
| `src/t.test.ts` | Tests de `t()`: clave, interpolación y clave ausente. |

La inicialización es sincrónica porque Astro genera las páginas en build (`output: 'static'`) y `t()` se llama en el frontmatter de los `.astro`. Nada se carga en tiempo de ejecución ni desde red: el JSON viaja dentro del bundle.

`interpolation.escapeValue` está en `false`: Astro y React ya escapan el texto que renderizan; escaparlo también aquí mostraría `&#39;` o `&amp;` en títulos con apóstrofes o ampersands.

## 2. Cómo usar una clave

En un `.astro` (frontmatter o plantilla):

```astro
---
import { t } from '@trayectoria/i18n';
---
<nav aria-label={t('nav.main')}>…</nav>
<title>{t('meta.title', { title })}</title>
```

En una isla React:

```tsx
import { useT } from '@trayectoria/i18n';

export function ThemeToggle(): JSX.Element {
  const t = useT();
  return <button aria-label={t('theme.toggle')}>…</button>;
}
```

Interpolación con la sintaxis de i18next: en el JSON `"minutes": "{{minutes}} min"`, en el código `t('topic.minutes', { minutes: 25 })`. Los parámetros son `string | number`.

**Las claves se escriben siempre como literales** (`t('nav.home')`, nunca `t(variable)` ni `t(\`nav.${x}\`)`): el test estático solo ve literales, así que una clave construida en tiempo de ejecución queda sin verificar.

## 3. Convención de claves

- Claves en **inglés**, notación de puntos, agrupadas por página o componente: `nav.home`, `theme.toggle`, `home.features.widgets.title`, `topic.previous` (`STANDARDS.md` §1).
- Valores en **español**. Español de referencia: el que ya usa `common.json`.
- Un texto = una clave. Si dos pantallas muestran la misma palabra con el mismo sentido, comparten clave; si el sentido cambia (`route.topics` = "temas" como etiqueta de conteo, `home.route.topicCount` = "{{topics}} temas"), son claves distintas.
- Qué es texto de UI (va por clave): etiquetas, botones, títulos de sección, `aria-label`, `title`, `placeholder`, `alt`, mensajes de estado, la descripción y la plantilla del `<title>` del layout.
- Qué **no** es texto de UI (no va por clave): el nombre de producto "Trayectoria" cuando se usa como marca, los títulos que vienen de `ruta.json` o del frontmatter de un tema, el contenido MDX, y los mensajes de error de build o `console` (en inglés, para desarrolladores).
- Puntuación estructural entre dos expresiones (` · `) puede quedar en la plantilla; lo que lleva letras va por clave.

## 4. Añadir una clave

1. Añade la clave a `packages/i18n/locales/es/common.json` en su grupo, con el valor en español.
2. Úsala en el código con `t('grupo.clave')` (Astro) o con el `t` de `useT()` (React).
3. Corre `pnpm --filter @trayectoria/i18n test`. `keys.test.ts` falla nombrando archivo y clave si escribiste mal la clave o te olvidaste del JSON:

   ```
   Keys used but not defined in common.json:
   apps/web/src/pages/index.astro: missing key "home.missing"
   ```

En tiempo de ejecución, una clave ausente no rompe nada: i18next devuelve **la propia clave** (`t('home.missing')` → `"home.missing"`). Por eso el test estático es la red de seguridad; no confíes en verlo en pantalla.

## 5. Añadir un idioma

Fuera de alcance de F0-06 (no hay traducciones ni selector de idioma). Cuando llegue el ticket:

1. Crea `packages/i18n/locales/<lng>/common.json` con **las mismas claves** que `es` (mismo árbol, valores traducidos). `es` es `fallbackLng`: una clave que falte en el idioma nuevo se muestra en español, no como clave.
2. Regístralo en `packages/i18n/src/t.ts`, en `resources`: `{ es: { common: es }, <lng>: { common: <lng> } }`.
3. El cambio de idioma se hace con la instancia (`i18n.changeLanguage('<lng>')`); las islas que usan `useT()` se re-renderizan solas. Cómo se elige y persiste el idioma (URL, cuenta, `localStorage` en un store) y cómo lo aplica Astro en build son decisiones de ese ticket, no de este documento.
4. El contenido MDX sigue su propia vía: `content/<lng>/` (`ARCHITECTURE.md` §3.3).

## 6. Widgets: sin literales de UI

`packages/widgets` no contiene texto de interfaz escrito a mano. Todo lo que ve el usuario sale de `t()`/`useT()` con una clave en `common.json` (también los `aria-label`, `DEFINITION-OF-DONE.md` tipo `widget`).

Lo aplica la regla ESLint local `i18n/no-ui-literals`, definida dentro de `eslint.config.js` (sin paquete adicional) para `packages/widgets/**/*.tsx`. Falla ante:

- Texto JSX con letras: `<button>Comprobar</button>`.
- Un literal de string (o plantilla sin expresiones) en los atributos `aria-label`, `title`, `placeholder` o `alt`: `<input placeholder="Masa en kg" />`, `<img alt={'Robot'} />`.

No falla ante números, símbolos o unidades sin letras en el texto, ni ante expresiones (`{t('exercise.check')}`, `{label}`). Es una comprobación sintáctica: un literal pasado por una variable (`const label = 'Comprobar'`) no lo ve; eso lo revisa el auditor de código contra este documento.

## 7. Comandos

```
pnpm --filter @trayectoria/i18n test        # keys.test.ts + t.test.ts
pnpm --filter @trayectoria/i18n typecheck
pnpm lint                                   # incluye i18n/no-ui-literals en packages/widgets
```
